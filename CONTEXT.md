# Graphic Agent — Domain Context

## Glossary

- **Scenario**: A YAML-declared visual generation task type (e.g. story_comic, game_assets, concept_art_board). Scenarios compose agents, evaluators, and renderers — they do not contain logic.
- **Asset**: A single visual artifact planned and generated by the pipeline. Comics have panels, game packs have props/icons/characters, concept boards have design variations.
- **AssetSpec**: The structured plan for one asset before generation, including prompt, size, difficulty estimate, and dependency declarations.
- **StyleGuide**: Immutable style memory created once per run, shared by all assets. Includes reference asset paths populated after initial generation.
- **ContextMemory**: Mutable blackboard that accumulates across revision rounds. Stores style patches, character descriptions, reference image paths, and revision lessons.
- **Evaluator**: A pluggable quality check registered by name. Scenario YAML declares which evaluators to run. Evaluators return `CritiqueIssue` lists; they contain no scenario-specific routing.
- **Critic**: Orchestrator that runs all declared evaluators and produces a `CritiqueReport`. Contains zero scenario-specific logic.
- **RevisionDecision**: The controller's output after reading a critique. Includes action (accept/retry/stop), prompt rewrites for failed assets, and a reasoning trace explaining the decision.
- **Prompt Rewrite**: A revised generation prompt produced by appending critique recommendations. MVP uses concatenation; future LLM-backed controllers do genuine rewriting.
- **CostSummary**: Per-run accounting of generation calls, retry calls, and per-asset attempt counts. Foundation for adaptive reasoning cost analysis.
- **Difficulty Estimate**: A 0-to-1 score on each AssetSpec predicting how hard it is to generate well. Used by future adaptive reasoning to allocate retry budget.
- **Depends On**: A list of asset IDs that must be generated before this asset. Used to build a DAG for future parallel generation.
- **Provider**: A mock or external API backend assigned to a model role. Providers are selected by configuration and must return structured pipeline objects.
- **Model Role**: A logical responsibility in the pipeline, such as planner, critic, or image generator. A model role maps to a provider and model version.
- **Provider Profile**: A named API usage recommendation that pins suppliers, model versions, quality settings, and cost assumptions for reproducible demos.
- **API Budget**: The expected and actual spend for one run, derived from model-role calls, generated image count, retry rounds, and provider pricing.

## Key Design Decisions

- **YAML declares, Python implements.** Scenarios never contain complex logic. If YAML starts to look like a DSL, the logic belongs in a Python module.
- **Evaluators are composable, not hardcoded.** The Critic delegates to a registry of evaluators. New scenarios never require modifying critic.py.
- **Prompt rewriting over blind retry.** Revision rounds apply critique recommendations to prompts rather than regenerating with unchanged prompts.
- **Transparency is the core differentiator.** Every pipeline step produces structured JSON. VisionCreator/CREA internalize reasoning; Graphic Agent externalizes it.
